# NEXUS LIVE — review-stage operating notes

This branch is not a deployment announcement. Do not enable collection or merge until the independent review and release checks below pass.

## Required configuration

Keep the defaults in `streaming/.env.example`: BGP off, IODA republication off, no CT sidecar. BGP activation requires explicit enablement, RIS terms acceptance, capacity approval, a named collector and a narrow prefix or origin-ASN scope. A filtered scope is not global coverage.

Prepare the ASN lookup offline using `streaming/live_bgp.py --input <reviewed-as.json> --source-commit <40-character-commit> --output <mapping.json>`. Input must come from that exact ipverse/as-metadata commit. The compiler filters authoritative country records and records a SHA256. Mount the compact mapping read-only and configure `LIVE_ASN_MAPPING_PATH`. Without mapping, observations remain unlocated; never guess a country. Do not run the full dataset compiler inside the small API worker.

Set the public HTTPS origin and the exact Caddy connection peer in `LIVE_TRUSTED_PROXY_IPS`; the Docker gateway may differ from loopback. Do not allow arbitrary forwarding-header trust. Keep one API worker and the existing memory/CPU limits. New SSE routes bypass buffering and access logging. Validate the actual Caddy configuration before reloading it.

## Acceptance checks before activation

- Human review and merge of each work package; high/critical findings fixed.
- Run Python live unit tests, existing database/WebSocket integration tests, JavaScript tests and the site checker. Docker and Caddy checks must run in CI or the intended deployment environment.
- Confirm source terms and full RIPE attribution, exact approved filters and pinned mapping provenance.
- Run a bounded passive capacity trial on the intended server. Record CPU, peak memory, bandwidth, accepted/rejected counts, gaps and existing-service health. Stop on limit breaches. No trial has been run for this branch.
- Exercise source disconnects, expired evidence, slow clients, reconnect gaps and hidden/paused browsers. Unknown or failed sources must not look like successful zero activity.
- Measure desktop and real mid-range phone performance before and after. Targets are 60/30 fps; these are not verified results. Check keyboard interaction, reduced motion, console errors and mobile layout.

## Evidence and compatibility

The new aggregate/evidence ring is in memory and is separate from legacy PostgreSQL observations. Evidence expires with its event and returns 410 after eviction. Replay frames are distinguished from fresh observations. Public evidence IDs are generated by the API; raw peer IDs are not exposed. Counts from the live ring must never be added to snapshot counts.

IODA legacy collection and public delivery are also gated by `IODA_REPUBLICATION_APPROVED=false`. Do not enable that flag without a recorded grant. No IODA or CT collector PR is claimed complete. Their exclusion is intentional, not an empty successful feed.

Rollback consists of disabling the new source and reverting the reviewed application/configuration release. Preserve the existing snapshot pipeline and legacy database; no database migration is required for the new in-memory layer.
