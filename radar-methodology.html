PRECISE MEANING.

NEXUS integrates public cybersecurity observations across multiple providers. Their methods, observation windows, and units are not interchangeable. We do not imply that every listed address is an attacker, that a CVE is confirmed on a specific host, or that ENISA's European incidents measure worldwide live risk.

Morocco southern geography — display and source-count separation

For the Morocco focus, NEXUS merges the adjacent Morocco and Western Sahara polygon geometries from the 1:110m Natural Earth / World Atlas source into a contiguous geographic display. Western Sahara is a disputed territory; the map presentation does not resolve its status. The underlying threat-indicator data is not merged: records carrying the MA source-country code retain their reported counts, and EH data is not relabeled or silently included in MA.

Country-specific CVE information

The CVE Signals country tab deliberately separates two types of evidence. Shadowserver's Dashboard supports country filtering for honeypot vulnerability exploitation observations and for vulnerable exposed web services. NEXUS opens these views on Shadowserver instead of scraping or republishing their country-level statistics. Shodan InternetDB may provide CVEs and ports for a small set of source IP indicator samples from the selected country. Shodan states that its vulnerability matches include both verified and unverified entries. This tiny, biased sample does not measure the country's most common vulnerabilities, prevalence, or national threat level. A missing result is not proof of safety.

Map and counter definitions

  • Unique listed IPs: deduplicated IPv4 union across feeds that were available during the collection. An address appearing in two feeds counts once in the union.
  • Geolocated indicators: listed IPs matched to a two-letter country code in DB-IP Lite. Unresolved indicators are excluded from country ranks.
  • Countries represented: number of countries with at least one geolocated indicator in the current snapshot. This is coverage of input lists, not an attack-rate ranking.
  • Selected source layer: counts from one feed only. Totals by feed overlap and must not be summed to get a global count.
  • Top CVEs: candidates from CISA KEV, ranked by an explicit heuristic: EPSS × 100 + 25 if ransomware-known + 10 if KEV-added within 30 days. This is not a standardized severity score and should not replace asset exposure or business context.

Geolocation and attribution

Country code relates to public IP infrastructure, not the person operating it. Hosting providers, cloud platforms, proxies, VPN services, compromised systems, recycling, and imprecise country-level databases can affect interpretation. We intentionally do not draw fictional attack arcs or infer targeted countries from source-only data.

Collection architecture

The collector sentinel/intelligence_pipeline.py uses Python standard libraries, checks input formats, deduplicates indicator sets, applies IP-range country lookups, and writes data/overview.json. A GitHub Actions workflow refreshes it every six hours. The frontend reads the published snapshot; GitHub Pages itself does not execute Python. On upstream failure, a source is marked unavailable, or the build fails if there is no usable feed. Some information may be hours old.

Responsible use

These threat-intelligence datasets should not automatically trigger blocking, exploit attempts, or attribution allegations. Use authorized active scanner modules separately, with explicit target scope. Feeds carry their providers' own licenses and terms independently of the MIT-licensed application source.

Provenance controls: each new source has an independent health record. Invalid schema, unavailable key, provider timeouts or size-limit failures are reported as unavailable; they are never transformed into synthetic zero counts. The parser caps compressed/download sizes, line counts, and output cardinality. No third-party strings are inserted as raw HTML.

Last updated and health timeline: the UTC clock refers to the latest collected snapshot, refreshed by the GitHub Actions schedule every six hours. The 28-run timeline records success, unavailable and not recorded statuses, but is not a network performance graph.
